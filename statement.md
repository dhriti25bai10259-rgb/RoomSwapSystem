# Project Statement

## Problem Statement

Students sometimes need to change rooms or roommates because of compatibility, personal needs, or hostel arrangements. Managing these requests manually through paper records or informal messages can cause delays, duplicate requests, and incorrect room assignments.

## Scope

The current console application allows hostel users to add and search students, view room availability, create room swap requests, and view request status. An administrator can accept or reject pending requests, and accepted requests exchange the students' room values. The system stores data only during program execution; it does not provide login, a database, persistent records, notifications, or a GUI.

## Target Users

- Students
- Hostel administrators

## High-Level Features

- Student registration and search by ID or name
- Room listing, status display, availability checking, and room addition
- Room swap request creation and request listing
- Admin acceptance or rejection of pending requests
- Automatic room exchange after acceptance
- Validation for IDs, names, email, rooms, menu choices, and processed requests
